# Учёт доходов и расходов по проектам

Веб-приложение для ручного учёта денег по проектам: доходы, расходы, прибыль
и рентабельность. Работает и само по себе, и вкладкой внутри Битрикс24.
Пользуются несколько сотрудников, у каждой операции виден автор.

Тестовое задание для «Аг Разработка».

## Быстрый запуск

Через Docker — одна команда, ничего доустанавливать не нужно:

```bash
docker compose up
```

Открыть http://localhost:8000

Без Docker (нужен Python 3.11+):

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload
```

Открыть http://localhost:8000

База создаётся сама при первом запуске, справочник статей из задания
заполняется автоматически. В варианте с Docker база лежит в папке `data/`
и переживает перезапуск контейнера.

## Что умеет

- **Проекты** — создание, список со сводкой, карточка с полной экономикой.
- **Статьи доходов и расходов.** Из задания заведены сразу: доход по проекту,
  внешние программисты, внутренние программисты, расходы на ИИ, аренда сервера,
  дивиденды. Свои статьи добавляются и удаляются в разделе «Статьи».
  Базовые удалить нельзя, свою — только пока по ней нет операций.
- **Операции** — сумма, дата, статья, комментарий, автор.
- **Сотрудники** — справочник и состав команды на каждом проекте.
  Кто именно работает сейчас, выбирается в шапке и запоминается в браузере;
  этот человек записывается автором операций.
- **Экономика проекта** — доходы, расходы, прибыль, рентабельность, разрез
  по статьям. Внизу сводки — итог по всем проектам.

## Как считаются деньги

Суммы хранятся в копейках целыми числами. Это осознанное решение: `float`
для денег даёт ошибки округления (классическое `0.1 + 0.2 != 0.3`), а целые
копейки складываются точно. Ввод разбирается через `Decimal`, поэтому
«1 234,56», «1234.56» и «1 234,56» читаются одинаково.

Рентабельность — отношение прибыли к доходам в процентах. Если доходов ещё
нет, показывается прочерк, а не ноль: проект с расходами и без выручки
убыточен, но базы для процента у него нет. Ноль означал бы «сработали в ноль»,
это другое.

## Встраивание в Битрикс24

Приложение умеет работать вкладкой внутри портала.

1. Приложение должно быть доступно по адресу из интернета (свой сервер,
   либо туннель вроде `ngrok http 8000` для проверки).
2. В портале: **Приложения → Разработчикам → Другое → Локальное приложение**.
3. Тип — «Приложение использует только API» снять, поставить вкладку.
   Путь обработчика: `https://ваш-адрес/b24/app`
   Путь для первоначальной установки: `https://ваш-адрес/b24/install`
4. Права доступа: достаточно `user` (чтение списка сотрудников).
5. Сохранить и установить. Приложение появится в левом меню портала.

После установки в разделе «Сотрудники» работает кнопка **«Загрузить
сотрудников»** — она забирает пользователей портала через метод `user.get`.
Повторный импорт не создаёт дублей: совпадение ищется по id пользователя
в Битрикс24.

Обновление токена по `refresh_token` намеренно не реализовано: Битрикс
присылает свежий токен при каждом открытии вкладки, а фоновых задач
у приложения нет. Если токен всё же протух, достаточно открыть приложение
в портале заново.

## Структура

```
app/
  main.py        роуты и обработка форм
  models.py      таблицы: проекты, статьи, операции, сотрудники, портал
  finance.py     расчёты: прибыль, рентабельность, разрез по статьям
  money.py       разбор и вывод сумм
  db.py          подключение к базе, справочник статей при первом запуске
  bitrix.py      установка в портал и импорт сотрудников
  templates/     страницы
  static/        стили
tests/           автотесты
```

Расчёты вынесены в отдельный модуль без обращений к базе — поэтому их можно
проверить тестами, не поднимая приложение.

## Тесты

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest tests -q
```

34 теста. Что проверяют:

- разбор сумм: пробелы, запятая вместо точки, округление до копейки, отказ
  на мусоре и отрицательных числах, отсутствие дрейфа float;
- прибыль и рентабельность, включая три краевых случая — нет доходов,
  отрицательная рентабельность, пустой проект;
- сквозной сценарий через HTTP: проект → операции → сводка, цифры на странице
  сверяются с ожидаемыми до копейки;
- защиту справочника: базовую статью удалить нельзя, статью с операциями тоже;
- работу команды: сотрудник на проекте, автор операции, снятие с проекта;
- каскадное удаление операций вместе с проектом;
- сохранение портала Битрикс24 при установке и понятную ошибку, если портала нет.

## Как проверялся результат

Код написан с Claude Code, но принят не «на глаз»:

1. Расчёты сверены вручную. На демонстрационных данных: доходы 2 070 000,00,
   расходы 1 080 400,50, прибыль 989 599,50, рентабельность 47,8 % —
   те же цифры получены отдельным счётом и совпали до копейки.
2. Приложение поднято локально, страницы открыты в браузере, снимки
   проверены глазами: сводка, карточка проекта, справочник, сотрудники.
3. Проверены краевые случаи, на которых обычно и ломается учёт денег:
   проект без доходов (рентабельность — прочерк, а не деление на ноль),
   сумма с копейками, ввод мусора вместо суммы, удаление проекта с операциями.
4. Первый прогон тестов нашёл три реальные проблемы: устаревшую сигнатуру
   рендеринга шаблонов в свежей версии Starlette, устаревший `datetime.utcnow`
   и точку вместо запятой в процентах. Все три исправлены.

## Ограничения

- Хранилище — SQLite. Для нескольких пользователей и такого объёма этого
  достаточно; при росте нагрузки меняется одна строка подключения на PostgreSQL.
- Отдельной авторизации нет: внутри Битрикс24 доступ уже ограничен порталом,
  а выбор «кто я» нужен для авторства операций, а не для защиты.
- Валюта одна — рубли.
